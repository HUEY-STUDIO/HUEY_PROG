# 연동 검증 현황

실제 공공 API 를 호출해 어디까지 확인됐는지 기록한다.
새 세션에서 작업을 이어갈 때 검증을 처음부터 반복하지 않기 위한 문서다.

최종 갱신: 2026-09-04 (3차 진단 — 국내망, 실인증키)

---

## 요약

| 단계 | API | 상태 |
|------|-----|------|
| 1 | 도로명주소 (주소 → PNU) | ✅ **실제 응답으로 검증 완료** |
| 1 | 브이월드 Geocoder (좌표) | ✅ **실제 응답으로 검증 완료** |
| 2 | NSDI 토지이용계획 / 토지특성 | ✅ **실제 응답으로 검증 완료** |
| 3 | 국가법령정보 (법령 조문) | ✅ **실제 응답으로 검증 완료** (호출 서버 IP 등록 후) |
| 4 | 자치법규 (조례 후보) | ✅ **실제 응답으로 검증 완료** (위와 동일 API) |
| 5 | 건축물대장 (건축HUB) | 🚧 **파이프라인에 미구현** — 키만 설정값에 존재, 호출 코드 없음 |

**2차 진단 대비 달라진 점**: 2차 진단은 클라우드 환경에서 실행되어
`api.vworld.kr` 이 호출 지점 차단으로 막혀 있었다. **국내망(로컬 PC)에서
실인증키로 재시험한 결과 1~4단계 전부 통과**했다. 남은 것은 코드 문제가
아니라 신청·설계 범위의 건축HUB 뿐이다.

```bash
python -m app.doctor
python -m app.cli "서울특별시 강남구 테헤란로 152"
```

## ✅ 검증 완료: 도로명주소 API

실제 응답을 받아 파서를 대조했고, 사용하는 필드명이 모두 실제와 일치한다.

**교차검증**: 조립한 PNU 가 응답의 `bdMgtSn`(건물관리번호) 앞 19자리와 일치.

```
입력   : 서울특별시 강남구 테헤란로 152
admCd  : 1168010100  lnbrMnnm: 737  lnbrSlno: 0  mtYn: 0
조립PNU: 1168010100107370000
bdMgtSn: 1168010100107370000023659   ← 앞 19자리 동일
```

**산(임야) 지번도 확인**:

```
제주특별자치도 서귀포시 중문동 산1-3 → 5013011200200010003
                                        └ 11번째 자리 '2' = 산, 본번 1, 부번 3
```

확인된 응답 필드: `roadAddr` `jibunAddr` `zipNo` `siNm` `sggNm` `emdNm`
`admCd` `lnbrMnnm` `lnbrSlno` `mtYn` (그 외 `bdNm` `rnMgtSn` `bdMgtSn` 등)

## ✅ 검증 완료: 브이월드 Geocoder / NSDI 토지 속성

국내망에서 실인증키로 호출한 결과 정상 응답을 받았다(2차 진단 때 겪은
"호출 지점 차단"은 그 실행 환경 고유의 네트워크 제약이었다).

**시험 주소**: 서울특별시 강남구 테헤란로 152 (강남파이낸스센터)

```
좌표: 37.50002857167398, 127.03651446855193
```

**토지이용계획** — 14건, 이 필지는 용도지역이 **둘** 걸쳐 있음을 확인:

```
일반상업지역 (UQA220, 저촉)
제3종일반주거지역 (저촉)
```

`pick_primary_zone()` 은 건폐율 상한이 높은 쪽(상업 80% > 주거 50%)을
대표로 선택 — 이 필지에서는 **일반상업지역**으로 올바르게 확정됨. 나머지는
경고로 노출(국토계획법 제84조 면적 안분 필요 안내).

**토지특성** — 18건, `stdrYear`(2013~2026) 별 이력이 누적되어 온다는 것을
실제로 확인. 정렬 순서가 보장되지 않아 `records[0]` 을 그대로 쓰면 옛 연도
값이 잡히는 버그가 있었다(2013년 공시지가 33,700,000 vs 최신 2026년
71,160,000). `land_use.pick_latest_year()` 로 `stdrYear` 최댓값을 고르도록
수정 완료.

파서(`extract_records`, `build_designations`)는 코드 수정 없이 실응답과
그대로 맞아떨어졌다 — 특정 키에 의존하지 않는 재귀 탐색 방식이 유효했다.

**확정된 올바른 호출 지점**(2차 진단에서 이미 코드 반영, 이번에 응답으로
재확인):

```
https://api.vworld.kr/ned/data/getLandUseAttr
https://api.vworld.kr/ned/data/getLandCharacteristics
  ?key=<발급키>&domain=<등록도메인>&pnu=<19자리>&format=json&numOfRows=100&pageNo=1
```

## ✅ 검증 완료: 국가법령정보 / 자치법규

`LAW_OC` 는 형식상 맞았으나, **호출 서버의 공인 IP 를 open.law.go.kr 에
등록**하기 전까지는 HTTP 200 에 아래 본문을 실어 인증 실패를 알렸다.

```json
{
  "result": "사용자 정보 검증에 실패하였습니다.",
  "msg": "OPEN API 호출 시 사용자 검증을 위하여 정확한 서버장비의 IP주소 및 도메인주소를 등록해 주세요."
}
```

이 응답 형태는 `app/services/law.py` 의 `raise_if_auth_error()` 가 감지해
실제 사유를 노출한다(그냥 두면 '결과 0건' 으로 보인다). IP 등록 후
재시험한 결과:

- 법령 목록 조회 — 건축법 / 건축법 시행령 / 건축법 시행규칙 3건 확인
- 자치법규(조례) 후보 — 40건 확인 (서울특별시 강남구 도시계획 조례 등)

**주의**: 이 IP 등록은 세션마다 바뀌는 클라우드 IP 가 아니라 **실제 서비스를
배포할 서버의 고정 IP** 로 다시 해야 한다. 로컬 PC 로 시험할 때도 공유기
재접속 등으로 공인 IP 가 바뀌면 재등록이 필요하다(`curl -s
https://api.ipify.org` 로 확인).

`--raw` 실패 경로에서 상류 응답 원문이 전혀 안 찍히던 문제도 함께 고쳤다
— `PublicApiError` 가 이제 `payload` 를 들고 다니며, `doctor.py` 가 실패
시에도 원본을 덤프한다. 성공 경로의 4000자 절단 상한도 20000자로 올리고
`--raw-limit` 옵션(0=무제한)을 추가했다(실측 토지특성 응답이 15,014자로
기존 상한이 73% 를 조용히 버리고 있었다).

## 🚧 미구현: 건축물대장 (건축HUB)

`DATA_GO_KR_SERVICE_KEY` 는 설정값(`app/config.py`)에는 있지만 **호출하는
코드가 아직 없다**. `app/services/` 에 해당 모듈이 없고, `pipeline.py`
`doctor.py` `cli.py` 어디에도 이 API 를 부르는 지점이 없다. README 의
파이프라인 다이어그램에도 이 단계는 등장하지 않는다.

2차 진단 당시(공공데이터포털 게이트웨이 오류코드로 경로/키 구분한 결과)
이 키는 건축HUB 에 대해 **미승인 상태(코드 30)**였다. 이번에 받은 키는
Encoding 값(`%2B`/`%2F`/`%3D` 포함)이라 그대로 쓰면 설령 승인됐어도
`SERVICE_KEY_IS_NOT_REGISTERED_ERROR` 가 날 가능성이 높다 — 포털에서
발급하는 **일반 인증키(Decoding)** 값으로 교체해야 한다.

**진행하려면**:
1. 공공데이터포털에서 건축HUB(`BldRgstHubService`) 활용신청 승인 여부 확인
2. Decoding 키로 `.env` 의 `DATA_GO_KR_SERVICE_KEY` 교체
3. `app/services/bldrgst.py` 신설 — PNU/지번으로 표제부(`getBrTitleInfo`) 조회
4. `pipeline.py` / `doctor.py` / `cli.py` / README 파이프라인 다이어그램에 반영

## 참고: 용도지역 둘 이상 겹침은 버그가 아니다

이 필지처럼 한 필지에 용도지역이 둘 이상 걸치는 경우가 실제로 있다.
`build_overview()` 는 이를 경고로 노출한다:

```
용도지역이 둘 이상 확인되었습니다(일반상업지역, 제3종일반주거지역).
둘 이상 걸친 대지는 국토계획법 제84조에 따라 면적 안분 등 별도 검토가
필요합니다.
```

`pick_primary_zone()` 은 대표값(건폐율 상한이 큰 쪽)을 자동 선택하지만,
실제 인허가 판단에는 면적 안분이 필요할 수 있어 경고를 남긴다. 정상 동작.

## 네트워크 관련 메모 (클라우드 세션 한정, 참고용)

2차 진단(클라우드 환경) 당시 겪은 문제로, 국내망 재시험으로 해소됐다.
클라우드에서 다시 진단할 일이 생기면 참고할 것.

- `https_proxy` 만 있고 `http_proxy` 는 없어 `http://` 호출이 프록시를 우회했다.
- `api.vworld.kr` 은 DNS·TLS 까지 성공하고 요청 직후 서버가 응답 없이
  연결을 끊었다(`Empty reply from server`) — 클라우드/해외 IP 차단으로 추정.
- `www.vworld.kr` `openapi.nsdi.go.kr` `www.nsdi.go.kr` 는 허용목록에 없어
  DNS/CONNECT 자체가 실패했다(문서 페이지를 열 때만 필요, API 호출과 무관).

## 새 세션에서 이어갈 때

1. **키 확인.** `.env` 가 없으면 `.env.example` 을 복사해 채운다
   (`docs/API_KEYS.md` 참고). `LAW_OC` 를 쓰려면 호출 서버의 공인 IP 를
   open.law.go.kr 에 등록해야 한다(`curl -s https://api.ipify.org`).

2. **진단부터 실행한다.**
   ```bash
   python -m app.doctor          # 단계별 통과/실패
   python -m app.doctor --raw    # 원본 응답 (파서 수정용)
   ```

3. **1~4단계는 이미 검증 완료.** 실패한다면 이번 코드 변경 이후 API 쪽
   사양이 바뀌었거나 키/IP 등록이 풀린 것이니 `--raw` 로 원본부터 본다.

4. **남은 확장은 건축HUB 뿐.** 위 "미구현: 건축물대장" 절의 4단계를 따른다.

5. 통과하면 실제 조회를 확인한다.
   ```bash
   python -m app.cli "서울특별시 강남구 테헤란로 152"
   ```
